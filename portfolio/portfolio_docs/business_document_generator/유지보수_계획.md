# AI-DPS (AI-enabled Dynamic Production System) 유지보수 계획

**작성일**: 2025-01-20  
**작성기관**: (주)블루어드에임즈  
**사업명**: AI-DPS (AI-enabled Dynamic Production System) - 스마트공장 고도화를 위한 AI 기반 생산 최적화 시스템  
**과제 지원분야**: 스마트공장 고도화

---

## 1. 유지보수 개요

AI-DPS는 기존 MES 인프라 위에 AI 레이어를 추가하는 통합 AI 플랫폼으로, 5계층 아키텍처(Frontend Layer, Backend API Layer, AI Services Layer, Data Pipeline Layer, Database Layer)로 구성됩니다. 본 문서는 시스템 구축 완료 후 지속적인 안정적 운영과 성능 최적화를 위한 유지보수 계획을 정리한 것입니다.

실제로 세아특수강 AMS 프로젝트에서도 동일한 방식으로 시스템을 구축하여 93.7%의 이상 탐지 정확도를 달성한 경험이 있으며, 본 사업에서도 동일한 원칙을 적용하여 지속적인 유지보수를 수행하겠습니다.

---

## 2. 유지보수 범위

### 2.1 시스템 구성 요소

AI-DPS는 다음과 같은 핵심 구성 요소로 이루어져 있으며, 각 구성 요소별로 체계적인 유지보수가 필요합니다:

**Frontend Layer**:
- 통합 대시보드 (React + TypeScript)
- 챗봇 인터페이스 (React + TypeScript)

**Backend API Layer**:
- Express.js RESTful API
- FastAPI AI 서비스 API
- WebSocket 실시간 통신

**AI Services Layer**:
- MLS 서비스 (머신러닝 전처리)
- FBS 시스템 (피쉬본 시스템)
- RMS 시스템 (룰 관리 시스템)
- AMS 통합 서비스 (베이지안 네트워크 분석)
- FMEA 생성 서비스

**Data Pipeline Layer**:
- PLC 신호 수집
- 검사기 데이터 수집
- 센서 데이터 수집

**Database Layer**:
- 관계형 데이터베이스 (정형 데이터)
- Neo4j 그래프 데이터베이스 (관계 데이터)
- PostgreSQL 통합 데이터베이스

### 2.2 유지보수 대상

유지보수 대상은 다음과 같이 구분됩니다:

**정기 유지보수**:
- 시스템 모니터링 및 성능 점검
- 데이터 수집 및 처리 파이프라인 점검
- AI 모델 성능 모니터링 및 재학습
- 데이터베이스 백업 및 복구
- 로그 관리 및 분석

**예방적 유지보수**:
- 정기적인 시스템 점검
- 성능 최적화
- 보안 업데이트
- 소프트웨어 업데이트

**응급 유지보수**:
- 시스템 장애 대응
- 데이터 손실 복구
- 보안 침해 대응

## 5. 성능 모니터링 및 평가

### 5.1 성능 지표

**기술적 성능 지표**:
- API 응답 시간: 평균 200ms 이하
- 데이터 처리량: 월 2,160만 건 이상
- 시스템 가용성: 99.9% 이상
- 에러 발생률: 0.1% 이하

**AI 모델 성능 지표**:
- 불량 예측 정확도: 85% 이상
- 설비 고장 예측 정확도: 80% 이상
- 불량 원인 규명 정확도: 90% 이상

**비즈니스 성과 지표**:

### 5.2 모니터링 도구

**시스템 모니터링**:
- 시스템 리소스 모니터링 (CPU, 메모리, 디스크, 네트워크)

**데이터 모니터링**:
- 데이터 수집 상태 모니터링
- 데이터 품질 모니터링

- 데이터베이스 성능 모니터링

**AI 모델 모니터링**:
- 모델 성능 지표 모니터링

## 6. 장애 대응 계획

### 6.1 장애 분류

**치명적 장애 (Critical)**:
- 시스템 전체 다운
- 데이터 손실
- 보안 침해
- 생산 라인 중단

**중요 장애 (Major)**:
- 주요 기능 동작 불가
- 성능 심각한 저하
- 데이터 수집 중단

**일반 장애 (Normal)**:
- 일부 기능 동작 불가
- 성능 일시적 저하
- 사용자 불편

**경미 장애 (Minor)**:
- 부차적 기능 문제
- UI 개선 사항
- 사용자 요청 사항

### 6.2 장애 대응 프로세스

**1단계: 장애 탐지**:
- 자동 모니터링 시스템을 통한 장애 탐지
- 사용자 신고 접수
- 로그 분석을 통한 장애 원인 추적

**2단계: 장애 분류 및 우선순위 결정**:
- 장애 심각도 평가
- 영향 범위 분석
- 우선순위 결정

**3단계: 장애 대응**:
- 임시 조치 (Workaround) 적용
- 근본 원인 분석 (RCA)
- 해결 방안 수립
- 장애 해결

**4단계: 사후 처리**:
- 장애 원인 분석 리포트 작성
- 재발 방지 대책 수립
- 문서 업데이트
- 사용자 안내
